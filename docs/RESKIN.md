# 程序员主题改造说明

## 已实现范围

当前为带关键对话选择的职业重开版，复用原有 core、condition、hooks 和随机引擎。内容改为入职日 + 36 个季度的职场历程，具有属性条件分支、事件前置、唯一经历、6 类结局和跨局档案。网页与终端共用同一套内容。

- 28 个天赋，包含互斥、分阶段触发、额外初始点数。
- 98 条事件记录（含里程碑、自动分支、结局）。
- 20 个成就、6 种预设职业出身。
- 主页、模式、天赋、属性、轨迹、复盘、成就、致谢的程序员主题文案与界面。
- 网页具备固定浅色主题、键盘可操作的天赋卡、手机适配、明确的单步推进与自动运行按钮。
- 使用独立命名空间保存已完成生涯的次数、天赋、事件与成就；原版 localStorage 不迁移、不删除。损坏的 JSON 和不合法 ID 不阻止启动。

本版在 8 个关键季度提供 25 个选项，日常季度继续使用自动事件；尚未加入工资经济系统或中途续档。界面与 README 已说明这些边界。内部沿用 `age` / `CHR` / `INT` 等字段以复用引擎，显示层统一为季度 / 沟通 / 技术 / 健康 / 积蓄 / 心态。

## REA 的使用与证据边界

基线为上游提交 f04888e202e5dfca0df48c51b8a099dc03cf08b4。参考工作区旁 `remake-analysis` 中现有 REA 6.8.0 静态证据、本地可行性报告，并重新执行：

```sh
rea trace-application-feature ../remake-analysis/trace-input.json --json
```

本次输出位于 `../remake-analysis/reskin-game-trace.json`：游戏入口匹配 9 个种子，追踪 23 个节点、36 条边，覆盖状态 partial。这是对原版固定快照的依赖分析，不是对改造后的完整动态证明。

据此核对 `Game -> hooks/play -> core/game -> state/talent/event/achievement -> data` 链路后修改。新主题不再依赖未生成的 Excel dist 模块，改为类型检查的 TS 源内容。

## 规则修复

1. 修正天赋次数表达式的 `??` 优先级，确保 `max > 1` 的天赋正确触发多次。
2. 缩放小数权重后再使用整数 RNG，避免 0.5/0.5 池永远抽到第一项；同时修复旧 Excel 转换器的一位小数缩放遗漏。
3. 天赋抽卡时排除已抽空的稀有度池，保证有库存时抽满 10 张。
4. 角色数量少于请求数量时按库存截断，避免返回空角色。
5. 对已经结束的生涯拒绝继续推进；缺少季度池时返回明确错误。
6. 在状态模块初始化 Immer MapSet，使单独使用事件、成就函数也能正常工作。
7. 修正网页与终端原有 `achievement` / `achievements` 导出名不一致。

## 验证

已执行 54 项规则/内容测试、3 项 hooks 事务测试、7 项网页存档测试（共 64 项），覆盖：条件表达式、天赋次数上限、权重边界、锁定天赋、角色池、6 类结局、提前退出、成就去重、完整季度池、ID 引用、分支无环、损坏档案恢复。

600 个固定种子的完整职业模拟均在最长 37 个回合内正常结束（含入职日），且每局恰好一个已知结局。针对六种预设背景得到的结局分布：技术专家 142、团队领航员 104、自由开发者 102、生活架构师 232、可靠的工程师 0、休整重启 20。模拟在每个决策点从可用选项中按种子选择；这是固定样本，不代表所有自由配点组合的真实概率或最终平衡目标。可靠工程师结局仍由独立可达性用例验证。

浏览器人工走通了自由创建、选三项天赋、分配含额外点数的属性、完整 36 季度、复盘、保留天赋、保存与刷新后成就恢复。类型检查与网页、终端生产构建也分别执行。
